# 文明精铺 — 美术资源需求规格

> 本文档定义 V2 版本所需的全量 3D 模型资源，供美术生成工作流使用。
> 游戏设计细节请参考 [game-design-v2.md](./game-design-v2.md)。

---

## 1. 技术规格

### 1.1 总体要求

| 项目 | 规格 |
|------|------|
| 模型格式 | GLB (glTF Binary) |
| 美术风格 | **低多边形 (Low-Poly)**，风格化手绘色彩，明快辨识度高 |
| 渲染引擎 | Three.js (WebGL)，PBR 材质 |
| 贴图 | 建议使用色板贴图 (colormap/palette) 或顶点着色，减小文件体积 |
| 单模型面数 | 底座 ≤ 1500 面，叠加件 ≤ 2000 面 |
| 文件大小 | 单个 GLB ≤ 200KB（含贴图） |
| 坐标系 | Y轴朝上，右手坐标系 |

### 1.2 模块化方案

V2 采用**模块化模型**方案：地形底座与叠加件（地貌/建筑）分离。

```
┌──────────────────┐
│  建筑/改良叠加件   │  ← 独立模型，放在底座顶面中心
├──────────────────┤
│  地貌叠加件(可选)  │  ← 如丘陵、森林、河流
├──────────────────┤
│   地形底座         │  ← 六角形底座，每种地形独立
└──────────────────┘
```

代码在渲染时按层叠放：底座 → 地貌 → 建筑。

### 1.3 六角底座规格

| 参数 | 值 | 说明 |
|------|------|------|
| 形状 | 正六边形 | **flat-top** 朝向（代码中旋转 π/6 适配 pointy-top） |
| 外接圆直径 | 1.0 单位 | 即六角边到对边中心距约 0.866 |
| 底座高度 | 0.05 ~ 0.2 单位 | 不同地形可有不同厚度（水域薄，山脉厚） |
| 原点 | 底座底面中心 | 方便代码中 Y=0 放置 |

### 1.4 叠加件规格

| 参数 | 值 | 说明 |
|------|------|------|
| 锚点 | 底部中心 (0, 0, 0) | 代码将其放置在底座顶面中心 |
| 占地范围 | 不超出底座六角边界 | 避免与相邻地块重叠 |
| 地貌高度 | 0.05 ~ 0.3 单位 | 丘陵/森林等自然元素 |
| 改良高度 | 0.1 ~ 0.4 单位 | 小型建筑/设施 |
| 区域高度 | 0.2 ~ 0.5 单位 | 大型建筑，需比改良明显更大 |

### 1.5 视觉辨识度要求

**核心原则**：玩家在正常游戏视角（45° 俯视）下，必须能一眼区分：

1. **不同地形底座** — 通过颜色、纹理、高度差异
2. **有无地貌** — 地貌叠加件足够醒目
3. **改良 vs 区域** — 区域建筑明显大于改良建筑
4. **不同建筑类型** — 每种建筑有独特剪影（silhouette），不依赖颜色区分

### 2.2 辨识度矩阵

下面列出容易混淆的地形对，以及如何区分：

| 容易混淆 | 区分方式 |
|---------|---------|
| 草地 vs 平原 | 草地偏绿、平原偏黄金色 |
| 草地 vs 稀树草原 | 草地饱满翠绿、稀树草原干燥泛黄+有小树 |
| 冻土 vs 冰原 | 冻土灰青有碎石、冰原纯白有冰晶 |
| 湖泊 vs 浅海 vs 深海 | 湖泊深蓝静水、浅海浅蓝+沙滩、深海藏蓝大波纹 |
| 山脉 vs 高原 | 山脉尖锐高耸、高原平坦有断层 |
| 沙漠 vs 平原 | 沙漠更亮更白、平原偏黄绿 |

## 10. 临时占位方案

在新模型完成之前，代码层面使用以下占位策略：

### 10.1 程序化底座占位

使用 Three.js `ExtrudeGeometry` 生成六角棱柱，通过不同颜色和高度区分地形：

```
每种地形 → 颜色(参考配色板) + 高度(参考底座厚度) → 程序化六角棱柱
```

### 10.2 程序化叠加件占位

| 类别 | 占位方式 |
|------|---------|
| 地貌 | 简单几何体（球体=丘陵，圆锥=森林/树，平面=河流/水） |
| 改良 | 小型方块+emoji文字精灵 |
| 区域 | 大型方块+emoji文字精灵 |

### 10.3 占位→正式模型切换

`model-mapping.ts` 中维护映射表。当正式模型 GLB 文件就位时，只需更新映射表中的文件名，无需改动其他代码。
